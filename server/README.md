# サーバー側（第2段階）

学習の記録をサーバーに預け、生徒・先生・運営者で見え方を分けるための仕組みです。
Xサーバーの標準機能（PHP・MySQL）だけで動きます。追加の契約は要りません。

## 中身

| ファイル | 役割 |
| --- | --- |
| `schema.sql` | データベースの設計 |
| `setup.php` | 表を作り、見本の利用者を入れる（コマンドから実行） |
| `config.sample.php` | 接続の設定の見本。**コピーして `config.php` を作ります** |
| `lib.php` | 共通処理。**権限の判定はここに集約** |
| `mail.php` | 保護者へのお知らせメールの組み立てと送信 |
| `api/login.php` | ログイン |
| `api/logout.php` | ログアウト |
| `api/whoami.php` | いま誰か（役割の判定に使う） |
| `api/record.php` | 学習の記録の受け渡し |
| `api/students.php` | 生徒の名簿と、在籍状態の変更 |
| `api/attendance.php` | 入退室の記録と、保護者へのお知らせ |
| `api/mailsettings.php` | メールの設定（運営者だけ） |
| `api/accounts.php` | アカウントの発行（運営者だけ） |
| `api/guardians.php` | 保護者の連絡先（運営者だけ） |
| `api/message.php` | 保護者へのご連絡・個別／一斉（運営者だけ） |

## いちばん大事なこと

画面側（`js/auth.js`）の出し分けは、**うっかり触らせないための目隠し**です。
端末の中を書きかえれば通せてしまいます。

ですから、**同じ判定を `lib.php` にも書いています**。
`lib.php` の `$PERMISSIONS` と `js/auth.js` の `PERMISSIONS` は同じ中身でなければならず、
`検証/t_server.py` が毎回突き合わせています。片方だけ直すと検証が落ちます。

## 手元（XAMPP）で動かす

```
# 1. データベースを起動（XAMPPコントロールパネルの MySQL でも可）
C:\xampp\mysql\bin\mysqld.exe --standalone

# 2. 設定を作る
copy server\config.sample.php server\config.php

# 3. 表と見本の利用者を用意する
C:\xampp\php\php.exe server\setup.php --sample

# 4. アプリごと動かす
C:\xampp\php\php.exe -S 127.0.0.1:8899 -t .

# 5. js/config.js を書きかえる
const SERVER_BASE = 'server/api/';
```

## Xサーバーへ移すとき

1. 管理画面でデータベースを作る（名前・利用者・パスワードを控える）
2. `config.php` をその値に書きかえる
3. `server/` フォルダをアップロードする
4. SSH で `php server/setup.php` を一度だけ実行する（`--sample` は付けない）
5. 運営者のアカウントを1件だけ手で作る
6. `js/config.js` の `SERVER_BASE` を書きかえる
7. `sw.js` の `CACHE` の版番号を上げる

**半日から1日**の見込みです。

## 気をつけること

- `config.php` は**公開リポジトリに置かないでください**（`.gitignore` に入れてあります）
- パスワードは `password_hash()` で保存し、**生のまま持ちません**
- サーバーとのやりとりは、サービスワーカーが**絶対に保存しない**設定にしてあります
  （保存すると、ログイン前の「あなたは生徒です」が残り続けます。2026-08-11に実際に起きました）
- `audit_log` に「誰がいつ何をしたか」が残ります。個人情報を扱う以上、跡は必要です
- 学習の記録は1人4MBまでにしています。上限が無いと、1人で保存領域を使い切れてしまいます

## アカウントの発行（2026-08-11 追加）

運営者の画面（マイページ →「アカウントの発行」）から、
**先生と生徒のアカウント**を作れます。教場も足せます。

### パスワードの扱い

- サーバーが自動で作ります。見まちがえやすい `0 O 1 l I` は使いません
- **発行の直後に一度だけ表示**します。こちらは変換後の値しか持たないため、
  あとから取り出すことはできません
- 忘れたときは「パスワードを作り直す」でやり直します（古いほうは使えなくなります）
- 記録（audit_log）にもパスワードは残しません

### 消さずに止める

アカウントは削除できません。消すと学習の記録も一緒に消えるためです。
代わりに「使えないようにする」で止めます（生徒の退塾と同じ扱いです）。
止めると、**すでに開いている画面もその場で使えなくなります**。

運営者は増やせず（F）、ご自身を止めることもできません。

### Xサーバーへ移したあとの最初の1件

`setup.php` を `--sample` なしで実行したあと、運営者を1件だけ手で作ります。

```sql
INSERT INTO venues (id, name) VALUES ('main', '本部教場');
INSERT INTO users (login_id, password_hash, role, name, enroll)
VALUES ('（お決めのID）',
        '（php -r "echo password_hash('"'"'お決めのパスワード'"'"', PASSWORD_DEFAULT);" の結果）',
        'admin', '佐藤 潤', 'active');
```

あとは画面から先生と生徒を発行できます。

## まだ作っていないもの

- オフラインで貯めた記録の、細かい突き合わせ
  （いまは「あとから保存したほうで上書き」です。1人が複数の端末を同時に使うと、
  片方の記録が消えます。教場の端末と自宅の端末を行き来する使い方が出てきたら、
  問題ごとの突き合わせに作り直す必要があります）

## 保護者へのお知らせメール（2026-08-11 追加）

生徒さんが入退室のQRを読み取ると、保護者の方へ自動でメールが届きます。
設定は運営者の画面（マイページ →「保護者へのお知らせメールの設定」）から変えられます。

### 送る／送らないの判断

| 状況 | 動き |
| --- | --- |
| 運営者が「切」にしている | 記録だけ残し、送らない（**既定はこちら**） |
| 保護者のメールが未登録 | 記録だけ残し、送らない |
| 休塾中の生徒 | 記録だけ残し、送らない |
| 3分以内に同じ知らせを送った | 送らない（連投を防ぐため） |
| 上記以外 | 送る |

**記録が先、メールが後**です。送信に失敗しても出席は必ず残ります。
また、生徒の画面は送信を待ちません（電波の悪い教場で待たされないため）。

### 差出人について

**Xサーバーで作ったメールアドレスをお使いください。**
GmailやYahooなど外部のアドレスを差出人にすると、
なりすましとみなされて迷惑メール扱いされ、届かないことがあります。

Xサーバーのドメインで作ったアドレスなら、送信元の証明（SPF）が
自動で設定されるため、届きやすくなります。

### 送信数の上限

Xサーバーの上限は **1時間1,500通／1日15,000通**です。
入退室で1人あたり1日2通なので、生徒300名でも1日600通。十分に収まります。

### 手元で試すとき

`settings` の `mail_dry_run` を `1` にすると、**実際には送らず**
`server/mail-dryrun.log` に書き出します。`setup.php --sample` が自動で `1` にします。

**本番へ移すときは、この行を消してください。**

```sql
DELETE FROM settings WHERE name = 'mail_dry_run';
```

### 気をつけたこと

- 件名・差出人名・宛先から改行を取り除いています。残すと、そこから先が
  別のヘッダー（Bccなど）として解釈され、知らない宛先へ送られてしまいます
- 本文に入れるのはお子さんの氏名・時刻・教場・学習時間だけです。
  ほかの個人情報は入れません
- 件名120文字・本文2000文字の上限を置いています

## 保護者へのご連絡（2026-08-12 追加）

### 保護者は何人でも登録できます

1人の生徒に、お父様・お母様・お祖母様など何人でもご登録いただけます
（名簿の各行 →「保護者の連絡先」）。

**入退室のお知らせを受け取るかは、お一人ずつ選べます。**
切にすると入退室の通知は届かず、個別・一斉のご連絡だけが届きます。

`users.parent_email` は名簿の一覧に出す代表の1件で、
`guardians` の先頭に自動でそろえています。送信に使うのは `guardians` のほうです。

### 個別送信と一斉送信

運営者の画面（マイページ →「保護者へご連絡する」）から送れます。

| | しぼりこみ |
| --- | --- |
| **まとめて送る** | 教場／在籍の状態（在籍・休塾・退塾・すべて） |
| **生徒を選んで送る** | 名簿から個別に選ぶ |

件名と本文に `{name}` と書くと、お子さんのお名前に置きかわります。

### 送る前に必ず下見できます

一斉送信は取り消せません。**「誰に届くか確かめる」で宛先と件数を見てから**
送っていただく形にしています。宛先はすべて表示し、多くても省きません。

- **宛先はお一人ずつ送ります。** まとめて送ると、ほかの保護者にアドレスが見えてしまいます
- **1回に送れるのは500通まで**です。Xサーバーの上限（1時間1,500通）に余裕を持たせています
- 送信が「切」のときは送れません
- 送った控えは `messages` に残り、画面からも確かめられます

### まだ作っていないもの

- 保護者ご自身が受信を止める仕組み（いまは運営者が連絡先を消します）
- 送信の失敗を運営者へ知らせる仕組み（いまは設定画面を開くと分かります）
